1. Che cos'è OCRLab

OCRLab è un'applicazione desktop per acquisire testo da immagini e PDF tramite OCR e per correggere il testo con un modello linguistico (LLM). È multipiattaforma (Windows e macOS) e progettata per essere completamente accessibile con screen reader (NVDA, VoiceOver) e sintesi vocale.

Supporta più motori OCR — Tesseract, Surya, Windows OCR, Apple Vision, modelli vision di Ollama/Unsloth e Chandra — e più provider di correzione (Ollama, Unsloth Studio, Google Gemini). Puoi scegliere il motore più adatto al tipo di documento e alla lingua.

2. Avvio e struttura dell'interfaccia

La finestra principale è organizzata in tre schede, selezionabili con Alt+1, Alt+2, Alt+3 o con le frecce sulla barra delle schede:

  1. Acquisizione — esegui l'OCR di un'immagine o di un PDF.
  2. Correzione — correggi un testo (anche il risultato dell'OCR) con un LLM.
  3. Impostazioni — scegli e configura i motori OCR e LLM.

In basso una barra di stato mostra l'operazione corrente. La prima volta configura almeno un motore nella scheda Impostazioni e premi Salva impostazioni.

Consiglio. Il flusso tipico è: Acquisizione → salvi il testo, oppure passi direttamente alla Correzione per rifinirlo con l'LLM.

3. Scheda Acquisizione (OCR)

Serve a estrarre testo da un file immagine o PDF.

  1. Premi Apri file (Ctrl+O) e seleziona un file .jpg, .jpeg, .png o .pdf.
  2. Premi Avvia OCR (F5). Una barra di avanzamento e l'etichetta "Pagina X di Y" indicano il progresso.
  3. Per fermare l'elaborazione premi Interrompi (Esc).
  4. Il testo compare nel riquadro Risultato OCR.
  5. Premi Salva risultato (Ctrl+S) per esportarlo.

Formati di salvataggio

  • Testo (.txt)
  • Documento Word (.docx)
  • PDF ricercabile (.pdf) — l'immagine originale con sopra il testo selezionabile e taggato per l'accessibilità.
  • HTML (.html) — disponibile solo quando il motore produce formattazione (es. Surya).

Le pagine multiple sono separate internamente da un carattere di avanzamento pagina.

4. Scheda Correzione (LLM)

Serve a correggere errori di OCR, refusi e formattazione usando un modello linguistico.

  1. Premi Apri file e carica un file .txt, .docx, .pdf o .html. Il testo appare in Testo originale.
  2. Premi Avvia correzione (F5). Il testo viene diviso in chunk ed elaborato in sequenza; l'avanzamento mostra "Chunk X di Y".
  3. Il risultato compare in Testo corretto; salvalo con Salva risultato in .txt o .docx.

Ripresa dopo un'interruzione

Se la correzione si interrompe (per esempio per un rate limit del servizio cloud o un errore di rete), OCRLab salva i chunk già corretti in un file di stato accanto al documento (.ocrlab-resume.json). Riaprendo lo stesso file compare "Ripresa disponibile: N di M chunk già corretti" e il pulsante Riprendi correzione continua dal punto d'interruzione. In caso di rate limit l'app riprova automaticamente con attese progressive.

Chunk e overlap. Dimensione dei chunk e sovrapposizione (overlap) si regolano nella scheda Impostazioni → sezione Chunking. Chunk più piccoli sono più robusti ma più lenti.

5. Scheda Impostazioni

In alto scegli quale sezione visualizzare con il selettore Mostra impostazioni: Acquisizione (motori OCR) o Correzione (motori LLM e chunking). Ricorda di premere Salva impostazioni in fondo.

Sezione Acquisizione

  • Motore OCR — scegli il motore (vedi capitolo 6). I campi visibili cambiano in base alla scelta.
  • Path Tesseract e Lingua predefinita OCR per Tesseract.
  • Modello VLM e pulsanti Modelli locali / scaricabili / cloud per Ollama Vision.
  • Lingua Windows OCR per Windows OCR.
  • Python per Surya / Surya 0.2 / Chandra — percorso del venv dedicato di ciascun motore.
  • Unisci parole spezzate da trattino a fine riga — ricompone le parole divise dal trattino di a-capo.

Sezione Correzione

  • Motore — Ollama, Unsloth Studio o Gemini.
  • Campi specifici del provider (URL, modello, chiave API).
  • Chunking — Dimensione chunk (token) e Overlap (token).

6. I motori OCR in dettaglio

Tesseract
OCR classico, veloce e locale. Richiede l'installazione separata di Tesseract e dei pacchetti lingua. Buono per documenti stampati e puliti.
Ollama Vision
Modelli vision (VLM) serviti da Ollama, in locale o via cloud Ollama. Adatto a layout complessi; richiede Ollama attivo.
Unsloth Vision
Modelli vision serviti da Unsloth Studio (server locale OpenAI-compatibile). Usa lo stesso URL e chiave API impostati nella sezione Correzione. Carica un modello con supporto vision prima di avviare l'OCR.
Windows OCR (solo Windows)
OCR nativo di Windows, gratuito e locale. Usa i pacchetti lingua installati dal sistema (Impostazioni → Ora e lingua → Lingua).
Apple Vision (solo macOS)
OCR nativo di macOS tramite il framework Vision. Gratuito e locale; richiede gli Xcode Command Line Tools (xcode-select --install).
Surya 0.1
Rileva la lingua automaticamente (90+ lingue), gestisce layout multi-colonna con rilevamento dell'ordine di lettura. Gira in un venv dedicato; al primo avvio scarica i modelli (~2 GB).
Surya 0.2
Versione più recente con migliore tipografia (corsivi, apici, note). Richiede un backend di inferenza esterno: Docker Desktop (GPU NVIDIA) oppure llama.cpp (CPU / Apple Silicon). Avvia il server dalla scheda Impostazioni.
Chandra
Modello VLM grande (~4B) per documenti complessi, tabelle e manoscritti. Richiede una GPU NVIDIA (consigliati 12 GB+ di VRAM) e usa quantizzazione 4-bit. Lento su hardware consumer (minuti per pagina).

7. I motori di correzione LLM

Ollama (locale o cloud)
Modelli LLM serviti da Ollama. Imposta URL del server, modello e — per il cloud — la chiave API. I pulsanti caricano i modelli locali, scaricabili o cloud.
Unsloth Studio (locale)
Server locale OpenAI-compatibile (di norma su http://127.0.0.1:8888). Opzioni aggiuntive: reasoning (modalità thinking, più lenta) e ricerca web (richiede un modello con supporto tool).
Gemini (cloud)
Google Gemini. Inserisci la chiave API e scegli il modello (es. gemini-2.5-flash).

9. Installare motori aggiuntivi

Alcuni motori si installano dall'app in un venv dedicato, dal menu Strumenti o dai pulsanti nella scheda Impostazioni:

  • Tesseract — su Windows usa "Installa Tesseract OCR..."; su macOS brew install tesseract. Le lingue si gestiscono da "Lingue Tesseract OCR...".
  • Surya 0.1 / 0.2 — "Installa Surya..."; richiede connessione internet e alcuni minuti. Surya 0.2 richiede inoltre Docker o llama.cpp.
  • Chandra — "Installa Chandra..."; scarica diversi GB e richiede una GPU NVIDIA.
  • Ollama — deve essere in esecuzione localmente sulla porta 11434.

Nota. Dopo l'installazione di un motore, riavvia OCRLab per poterlo utilizzare.

10. Risoluzione dei problemi

"Tesseract non trovato"
Installa Tesseract e/o imposta il percorso dell'eseguibile in Impostazioni → Path Tesseract.
Nessuna lingua Windows OCR
Aggiungi un pacchetto lingua da Impostazioni di Windows → Ora e lingua → Lingua → Aggiungi una lingua.
Errore di connessione Ollama/Unsloth
Verifica che il server sia in esecuzione e che URL e chiave API siano corretti.
La correzione si ferma su rate limit
È normale con i servizi cloud: l'app riprova da sola e, se serve, usa Riprendi correzione.
Surya/Chandra molto lenti
Sono modelli pesanti; senza GPU adeguata i tempi salgono a minuti per pagina. Preferisci Tesseract o Windows/Apple Vision per documenti semplici.

1. What OCRLab is

OCRLab is a desktop application to capture text from images and PDFs via OCR and to correct that text with a language model (LLM). It is cross-platform (Windows and macOS) and designed to be fully accessible with screen readers (NVDA, VoiceOver) and speech synthesis.

It supports several OCR engines — Tesseract, Surya, Windows OCR, Apple Vision, Ollama/Unsloth vision models and Chandra — and several correction providers (Ollama, Unsloth Studio, Google Gemini). You can pick the engine best suited to your document type and language.

2. Launch and interface layout

The main window has three tabs, reachable with Alt+1, Alt+2, Alt+3 or the arrow keys on the tab bar:

  1. Acquisition — run OCR on an image or PDF.
  2. Correction — correct text (including OCR output) with an LLM.
  3. Settings — choose and configure the OCR and LLM engines.

A status bar at the bottom shows the current operation. On first use, configure at least one engine in the Settings tab and press Save settings.

Tip. The typical flow is: Acquisition → save the text, or go straight to Correction to polish it with the LLM.

3. Acquisition tab (OCR)

Used to extract text from an image or PDF file.

  1. Press Open file (Ctrl+O) and pick a .jpg, .jpeg, .png or .pdf file.
  2. Press Start OCR (F5). A progress bar and a "Page X of Y" label show progress.
  3. To abort, press Stop (Esc).
  4. The text appears in the OCR Result box.
  5. Press Save result (Ctrl+S) to export it.

Save formats

  • Text (.txt)
  • Word document (.docx)
  • Searchable PDF (.pdf) — the original image with selectable, accessibility-tagged text on top.
  • HTML (.html) — available only when the engine produces formatting (e.g. Surya).

Multiple pages are internally separated by a form-feed character.

4. Correction tab (LLM)

Used to fix OCR errors, typos and formatting with a language model.

  1. Press Open file and load a .txt, .docx, .pdf or .html file. The text appears in Original text.
  2. Press Start correction (F5). The text is split into chunks processed in sequence; progress shows "Chunk X of Y".
  3. The result appears in Corrected text; save it with Save result as .txt or .docx.

Resuming after an interruption

If correction is interrupted (for example by a cloud rate limit or a network error), OCRLab saves the already-corrected chunks in a state file next to the document (.ocrlab-resume.json). Reopening the same file shows "Resume available: N of M chunks already corrected" and the Resume correction button continues from where it stopped. On rate limits the app retries automatically with increasing back-off.

Chunk and overlap. Chunk size and overlap are set in the Settings tab → Chunking section. Smaller chunks are more robust but slower.

5. Settings tab

At the top, choose which section to show with the Show settings selector: Acquisition (OCR engines) or Correction (LLM engines and chunking). Remember to press Save settings at the bottom.

Acquisition section

  • OCR Engine — choose the engine (see chapter 6). The visible fields change with your choice.
  • Tesseract path and Default OCR language for Tesseract.
  • VLM Model and the Local / Downloadable / Cloud model buttons for Ollama Vision.
  • Windows OCR language for Windows OCR.
  • Python for Surya / Surya 0.2 / Chandra — path to each engine's dedicated venv.
  • Join hyphenated words at line end — rejoins words split by an end-of-line hyphen.

Correction section

  • Engine — Ollama, Unsloth Studio or Gemini.
  • Provider-specific fields (URL, model, API key).
  • Chunking — Chunk size (tokens) and Overlap (tokens).

6. OCR engines in detail

Tesseract
Classic, fast, local OCR. Requires installing Tesseract and language packs separately. Good for clean printed documents.
Ollama Vision
Vision models (VLM) served by Ollama, locally or via Ollama cloud. Good for complex layouts; requires Ollama running.
Unsloth Vision
Vision models served by Unsloth Studio (a local OpenAI-compatible server). Uses the same URL and API key set in the Correction section. Load a vision-capable model before running OCR.
Windows OCR (Windows only)
Native Windows OCR, free and local. Uses the language packs installed by the system (Settings → Time & language → Language).
Apple Vision (macOS only)
Native macOS OCR via the Vision framework. Free and local; requires the Xcode Command Line Tools (xcode-select --install).
Surya 0.1
Auto-detects the language (90+ languages) and handles multi-column layouts via reading-order detection. Runs in a dedicated venv; downloads its models (~2 GB) on first run.
Surya 0.2
Newer version with better typography (italics, superscripts, notes). Requires an external inference backend: Docker Desktop (NVIDIA GPU) or llama.cpp (CPU / Apple Silicon). Start the server from the Settings tab.
Chandra
Large VLM model (~4B) for complex documents, tables and manuscripts. Requires an NVIDIA GPU (12 GB+ VRAM recommended) and uses 4-bit quantization. Slow on consumer hardware (minutes per page).

7. LLM correction engines

Ollama (local or cloud)
LLM models served by Ollama. Set the server URL, the model and — for cloud — the API key. The buttons load local, downloadable or cloud models.
Unsloth Studio (local)
Local OpenAI-compatible server (usually at http://127.0.0.1:8888). Extra options: reasoning (thinking mode, slower) and web search (needs a tool-capable model).
Gemini (cloud)
Google Gemini. Enter the API key and choose the model (e.g. gemini-2.5-flash).

  • The interface language takes effect after restarting the application.

9. Installing extra engines

Some engines install from within the app into a dedicated venv, from the Tools menu or the buttons in the Settings tab:

  • Tesseract — on Windows use "Install Tesseract OCR..."; on macOS brew install tesseract. Languages are managed from "Tesseract OCR languages...".
  • Surya 0.1 / 0.2 — "Install Surya..."; needs an internet connection and a few minutes. Surya 0.2 also requires Docker or llama.cpp.
  • Chandra — "Install Chandra..."; downloads several GB and requires an NVIDIA GPU.
  • Ollama — must be running locally on port 11434.

Note. After installing an engine, restart OCRLab to use it.

10. Troubleshooting

"Tesseract not found"
Install Tesseract and/or set the executable path in Settings → Tesseract path.
No Windows OCR language
Add a language pack from Windows Settings → Time & language → Language → Add a language.
Ollama/Unsloth connection error
Check the server is running and that the URL and API key are correct.
Correction stops on a rate limit
Normal with cloud services: the app retries on its own and, if needed, use Resume correction.
Surya/Chandra very slow
These are heavy models; without a suitable GPU, times rise to minutes per page. Prefer Tesseract or Windows/Apple Vision for simple documents.
